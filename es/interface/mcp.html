Servicios MCP ​

MCP (Model Context Protocol) es el estándar por el que un agente gana herramientas que no venían de fábrica. La pantalla registra dos tipos bastante distintos, y la elección se hace al crear:

  • Externo — un servidor MCP de un tercero, que consumes por URL.
  • Propio — un servidor que tú escribes aquí, y que la plataforma publica.

Externo ​

Basta el transporte, la URL y el tiempo límite. Nada se ejecuta en tu instalación — la plataforma solo habla con la dirección indicada.

Tras guardar, vincula el servicio a un agente en la pestaña Herramientas del agente.

Propio ​

Aquí escribes las herramientas en Python y la plataforma levanta un servidor MCP para ellas, en un proceso aparte — un servicio MCP lento nunca bloquea una petición de la API.

Pestaña Herramientas ​

Cada función de nivel superior se convierte en una herramienta. No escribas decorador ni ruta: la plataforma envuelve las funciones y monta el register_tools sola. El nombre, la firma y el docstring son el contrato que el modelo lee para decidir cuándo llamarla.

El ámbito trae log() y las operaciones de datos, sistema e integración — ver MCP Propio.

Pestaña Auxiliares ​

Código de apoyo: import, constantes y funciones compartidas. Nada de aquí se convierte en herramienta, aunque sea función de nivel superior. Es la separación entre "lo que el modelo puede llamar" y "lo que tu código usa por dentro".

Pestaña Autenticación ​

Tres llaves, y vale entender qué abre cada una:

  • Token fijo — un secreto que el llamante presenta. Es lo que entregas a un cliente fuera de la plataforma.
  • Aceptar token de workflow — permite que workflows y planificadores de la propia instalación llamen al servicio sin token propio.
  • Aceptar autenticación de usuario — permite que un usuario conectado llame, respetando sus grupos.

Apagar las tres deja el servicio publicado e inalcanzable.

Pestaña Versiones ​

Cada guardado conserva una versión del código. Se puede comparar, restaurar y anotar una observación en cada una — el historial es lo que permite tocar un servicio que ya está en uso sin miedo.

Publicar ​

El servicio propio solo entra en el aire tras publicarse, y corre en el puerto de su registro. Cada servicio tiene el suyo.

La publicación se reconcilia, no es instantánea

El proceso que sirve los MCP compara periódicamente lo que está en el aire con lo que está en la base. Tras publicar, el endpoint aparece en segundos — no en el mismo instante del clic.

Probar llama a la herramienta directamente desde la pantalla, sin pasar por un agente. Es la forma de separar "la herramienta está mal" de "el modelo no la eligió".
