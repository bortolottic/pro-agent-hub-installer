Planejador de Execução — ferramentas ​

As operações que um Planejador pode acionar durante o loop. É uma lista liberada por você na tela do planejador: nada roda sem estar marcado ali.

Agentes e times NÃO aparecem aqui — eles são acionados pelos executores cadastrados no planejador, que é o catálogo que o modelo enxerga na hora de montar o plano.

Estão disponíveis 18 símbolos neste contexto.

Remove registros de uma tabela da conexão de banco cadastrada.

Args: database_connection_id: ID da DatabaseConnection cadastrada no ProAgent Hub table: nome da tabela (ex: 'app.my_table') where: dicionário coluna → valor para filtro (cláusula WHERE) user_name: usuário da plataforma para autorização (padrão: 'projjetta')

install_python_package(package: str, timeout: int = 300) ​

Instala biblioteca(s) Python no ambiente atual (.venv) via pip.

Aceita especificação de versão (ex.: pandas==2.2.0). Retorna a saída do pip.

O pacote fica importável JÁ NESTA execução: o pip instala em disco, mas o processo em curso mantém em cache o conteúdo dos diretórios de sys.path, e sem invalidar esse cache o import seguinte ainda falharia com ModuleNotFoundError — instalar e continuar sem poder usar não serve para nada em um loop que instala justamente para usar em seguida.

ParâmetroTipoPadrão
packagestrobrigatório
timeoutint300

run_python_code(code: str, timeout: int = 300) ​

Executa código Python dinâmico e retorna o stdout (ou o traceback do erro).

Se a ÚLTIMA linha do código for uma expressão, o valor dela também entra na saída — como num notebook. Quem gera o código costuma terminar com o nome da variável do resultado (valores) esperando recebê-lo de volta; sem isso o exec descartava o valor em silêncio e a resposta vinha vazia, o que é indistinguível de "não achei nada" para quem chamou.

scope é preenchido pela PLATAFORMA (nunca por quem escreve o código) com as funções que o chamador libera — é assim que o planejador entrega db_query, db_insert e companhia já prontas, com a conexão cadastrada. Sem isso o código não tinha como falar com o banco e o modelo acabava inventando um psycopg2.connect com usuário e senha imaginários.

timeout fecha um buraco que as irmãs já não tinham (run_shell_command para em 120s, install_python_package em 300s): um while True ou um requests sem timeout escrito pelo modelo travava a execução inteira. O planejador só verifica os limites ENTRE passos, então um passo que não volta nunca é um loop que não termina — e, na API, um worker do gunicorn preso.

A execução roda em uma thread própria e, esgotado o prazo, ela é abandonada, não morta: Python não interrompe uma thread com segurança. Quem chama recupera o controle e pode replanejar; o código largado segue até terminar sozinho (e morre com o processo, por ser daemon). É a troca honesta — abandonar uma thread é ruim, ficar preso para sempre é pior.

Use para cálculos, parsing ou transformações pontuais. Não execute código derivado de conteúdo não confiável.

ParâmetroTipoPadrão
codestrobrigatório
timeoutint300
