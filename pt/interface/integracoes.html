Integrações ​

Levam um agente ou time para onde as pessoas já conversam — WhatsApp, Teams, Telegram, e-mail — em vez de pedir que elas entrem na plataforma.

Desde a versão 1.0.26.7 a plataforma não fala mais com cada canal por conta própria: as integrações de WhatsApp (Evolution API) e de Microsoft Teams foram retiradas. Quem fala com o canal é o N8N, que já tem um nó pronto para cada um deles. A plataforma cuida do que é dela: o agente, o time, o workflow.

Do canal para a plataforma ​

O caminho é sempre o mesmo:

  1. um fluxo do N8N recebe a mensagem do canal (o gatilho do WhatsApp, do Teams…);
  2. um nó HTTP Request chama o workflow da plataforma que conversa com o agente;
  3. a resposta do workflow volta ao canal pelo nó de envio do próprio N8N.

A chamada é o disparo de workflow por API:

POST /api/workflow/<id>/run
Authorization: Basic <token de API dos workflows>
X-Impersonate-User: <usuário da plataforma>   (opcional)
Content-Type: application/json

{ "mensagem": "texto recebido", "remetente": "..." }

O corpo vira o contexto da execução, e a resposta traz o resultado do workflow na hora — não é preciso consultar depois. O token é o da tela de Administração, e o X-Impersonate-User decide em nome de quem o workflow roda: sem ele, roda como o usuário de serviço.

Quem escreveu a mensagem

O que vem do canal — nome, número, e-mail — é escrito por quem mandou a mensagem. Passe esses campos ao agente como dado, nunca como instrução, e não os use para decidir permissão.

Da plataforma para o N8N ​

Cadastro em Configurações → aba N8N, restrito a master.

Uma integração N8N guarda o endereço da instância (ex.: https://n8n.empresa.com, ou https://empresa.com/n8n se o N8N roda num subcaminho; nunca com /webhook/), a autenticação do webhook e o prazo padrão das chamadas.

Autenticação. O nó Webhook do N8N oferece Header Auth, Basic Auth, JWT Auth ou nenhuma. Todas cabem no par cabeçalho/valor do cadastro:

No nó WebhookCabeçalhoValor
Header Autho Name da credencialo Value da credencial
Basic AuthAuthorizationBasic + base64 de usuário:senha
JWT AuthAuthorizationBearer + o token

O segredo nunca volta à tela: ao editar, deixe o campo em branco para manter o atual, ou marque Remover o segredo atual. Ele também não fica no workflow — o fluxo guarda só o número da integração e o caminho do webhook, e é por isso que quem monta o workflow não consegue mandar a chamada para outro lugar.

Em Avançado ficam os prefixos webhook e webhook-test. Só mude se a instância do N8N os trocou pelas variáveis N8N_ENDPOINT_WEBHOOK e N8N_ENDPOINT_WEBHOOK_TEST.

No workflow high-code (ou num nó Script), a chamada é:

python
resposta = call_n8n(1, "pedido-aprovado", {"pedido": 123, "cliente": "ACME"})
  • o primeiro argumento é o número da integração (aparece na lista da aba);
  • o segundo é o Path do nó Webhook; com parâmetros de caminho, informe os valores (o Path pedido/:id vira "pedido/123");
  • o terceiro são os dados: vão como JSON no corpo (no N8N, $json.body); em GET e HEAD, viram parâmetros da URL ($json.query). O N8N limita o corpo a 16 MB.

O método é o HTTP Method do nó (method="GET", por exemplo; o padrão é POST). A resposta depende do Respond do nó Webhook:

RespondO que call_n8n devolve
Immediatelya mensagem de que o fluxo começou — ele segue sozinho
When Last Node Finishesa saída do último nó
Using 'Respond to Webhook' Nodeo que aquele nó definir

JSON vira dicionário, texto vira texto e arquivo (um PDF, por exemplo) vira bytes. A URL de produção só existe com o fluxo publicado no N8N; a de teste (test_mode=True) só responde enquanto o editor está em Listen for test event, por 120 segundos. Webhook não registrado responde 404, e a mensagem de erro diz isso. No N8N Cloud, um fluxo que não responde em 100 segundos falha.

Uma falha — integração desabilitada, rede, resposta de erro do N8N — levanta N8nCallError, com status e body quando o N8N respondeu. A referência completa está em Funções.

No workflow low-code ​

O nó N8N (grupo Integrações da paleta) faz a mesma chamada sem código: escolha a integração, informe o caminho do webhook (aceita {{variavel}}, como em pedido/{{pedido_id}}), o método e os dados — uma variável, uma referência {{no.campo}} ou um JSON com variáveis. A resposta vai para a variável de saída (n8n_result). O nó tem duas saídas, OK e ERRO, como o nó Planejador: a falha desvia por ERRO quando ela está ligada, e o motivo fica em {{nome_do_no.n8nError}}. Quando falhar escolhe entre continuar, parar o caminho ou falhar o workflow.

Ao exportar as configurações, as integrações N8N vão junto, com o segredo cifrado como as demais senhas.
